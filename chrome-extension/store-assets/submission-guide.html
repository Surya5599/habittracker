4. Privacy Practices tab

This is the questionnaire that actually gets your submission rejected if answered vaguely. Answer exactly as below — it matches what the shipped code (manifest.json, src/content.ts, src/supabase.ts) actually does, which is what reviewers cross-check against in 2026.

Single purpose description

HabiCard is a habit-tracking companion that lets a signed-in HabiCard user view and update their daily habits, tasks, and journal entries from a browser-toolbar popup, kept in sync with their account on habicard.com.

Permission justifications

storageStores the user's Supabase authentication session locally (chrome.storage.local) so they stay signed in between popup opens, and stores the "compact vs. large" card-density display preference. No data is stored for any purpose beyond running the signed-in user's own session.
Host permission: habicard.com, *.habicard.com, localhost (content script)A content script runs only on these domains to read the existing web-app login session from that page's localStorage and mirror it into the extension's storage, so a user who is already signed in on habicard.com doesn't have to sign in again in the popup. It does not read, modify, or inject anything into any other page or any other site.
There is no host_permissions block and no broad <all_urls> access anywhere in the manifest — if the form asks "does this extension request access to all URLs," the answer is No.

Remote code

Does this extension use remote code? No. content_security_policy.extension_pages is script-src 'self' — all JavaScript ships inside the package; nothing is fetched and executed at runtime. Network calls (to Supabase) only exchange data, never code.
